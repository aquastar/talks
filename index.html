Defining "AI"

Which "AI" are we talking about?

AI: programs that do something we would call intelligent, such as chess engines, route planners and robots.
Machine learning: the rules are learned from data instead of written by hand, as in spam filters, recommenders, and image classifiers.
Generative AI: models that produce new content such as images, audio or text.
Large language models: generative models of text. Most of today's "AI" hype.
~45 s. Four clicks, starting from the outer circle. The rest of the talk is about the innermost one. When someone says "AI will…", it is worth asking which of these they mean.

Agents and the software around the model

Four terms, defined precisely

Model
A file of numbers (the weights) plus the math to run them. Given a sequence of tokens, it returns probabilities for the next token. On its own it has no memory between calls and cannot run code, open files or browse.
e.g. GPT-6, Claude Opus 5.5, Llama
Tool
A function that the harness offers to the model. The model is shown its name, a plain-language description and a parameter schema. It "calls" a tool by writing a structured request as text. It never executes anything itself.
e.g. run(cmd), read_file(path), web_search(query)
Harness
The ordinary program wrapped around the model (also called a scaffold or agent runtime). It assembles the prompt, lists the tools, executes or refuses each tool call, pastes results back, enforces permissions and sandboxing, trims the context and decides when to stop.
e.g. the ChatGPT and Claude apps, Claude Code, Codex CLI, Cursor, Copilot
Agent
A model and a harness running in a loop, where the model chooses the next action based on the results so far, until it decides the goal is met or a limit is hit. Simon Willison's one-line version: "An LLM agent runs tools in a loop to achieve a goal."
a chatbot is the degenerate case: one turn, few or no tools
When you read "the AI did X", ask whether the model chose X or the harness was programmed to do it. The answer decides where responsibility and control live.

Willison (2025)

~1.5 min. These four words are used loosely in the press; the rest of Part 3 uses them in exactly these senses. The key point: the model only ever produces text. Everything that touches the world is done by the harness, which is ordinary software we know how to reason about.

The software around the model

If the model is the CPU, the harness is the operating system, and it is ordinary code. Agents improved in 2025 from both: models trained on checkable tasks, and better harnesses.
~1.5 min. Four clicks, one box each. The model never touches a file, a shell or the network directly. The harness does, and it decides what the model is allowed to request. MCP (Model Context Protocol) came from Anthropic in 2024, was adopted by OpenAI and Google in 2025, and has been under the Linux Foundation since Dec 2025. Each box matches a research area in this department.

RAG: retrieval-augmented generation

Definition: at question time, search a collection of documents for relevant passages and paste them into the context window along with the question, so the model answers from those passages instead of from what it memorized in training.

Embedding: a vector (say, 1,024 numbers) computed from a chunk of text so that passages with similar meaning land near each other. Retrieval is nearest-neighbor search in that space, often combined with ordinary keyword search.
RAG vs. fine-tuning: RAG changes what is in the window; fine-tuning changes the weights. Edit the syllabus and RAG answers change immediately, with no retraining.
Failure modes: if retrieval misses the right passage, the model usually answers anyway, fluently. Retrieved text can also carry hidden instructions (prompt injection, below). Web search in ChatGPT or Claude is RAG with a search engine as the retriever.

Lewis et al. (2020) coined the term.

~1.5 min. Three clicks through the pipeline, then two for the cards. RAG is a database query plus copy-paste into the prompt. It reduces hallucination when retrieval works, and does nothing when it doesn't. Most "chat with your course materials" tools that vendors pitch are RAG workflows.

MCP: a standard plug between harnesses and tools

Definition: the Model Context Protocol is an open protocol (Anthropic, Nov 2024) for how a harness, the MCP client, discovers and calls programs called MCP servers, which offer tools and data. Messages are JSON-RPC, over stdio for local servers or HTTP for remote ones.

What a server offers: tools (functions to call), resources (data to read) and prompts (reusable templates). Write a server once and any MCP client can use it, so M apps × N services becomes M + N integrations. The idea is borrowed from the Language Server Protocol that editors use.
What the model actually sees: each server's tool names and descriptions, pasted into the context as text. MCP gives the harness reach; it does not make the model any smarter.
Why it matters for security: a tool description is prompt text written by whoever wrote the server, so a malicious or careless server is an injection channel. Permission checks still have to live in the harness.

modelcontextprotocol.io. Adopted by OpenAI and Google in 2025; governed under the Linux Foundation since Dec 2025.

~1.5 min. For CS faculty, the LSP analogy usually lands immediately. "Connectors" and "integrations" in consumer apps are usually MCP servers under the hood. The servers on the diagram are examples of the kinds that exist, not an endorsement.

Splitting work across several agents

Why split: a single context window fills up. Claude Code added agent teams in February 2026, and Codex added subagents in March. Each agent gets its own window and can work in its own copy of the repo.
Does it help? In Anthropic's research system (June 2025), a lead agent with parallel sub-agents did 90% better than a single agent on research tasks, using about 15× the tokens of a normal chat. It works when the task splits cleanly, less well when the parts depend on each other.
The reviewer does the job of the test check in the agent loop. DeepMind's AlphaEvolve (2025) goes further: Gemini proposes code, an evaluator scores it, and the best versions are kept and varied. It multiplied 4×4 complex matrices with 48 multiplications (Strassen's 1969 method needs 49) and sped up a Gemini training kernel by 23%.
Limits: the reviewer has the same blind spots as the workers, and costs add up. Shared files, locking, and deciding when the work is finished are distributed-systems problems.

Sources: Anthropic (2025); Novikov et al. (2025); Claude Code docs.

~2 min. Four clicks. 1: the lead agent's window is nearly full. 2: three workers run in parallel. 3: their changes go to a reviewer that runs the tests, and C fails. 4: C gets the work back, the second round passes, and the lead merges. AlphaEvolve follows the same pattern, using selection in place of a lead agent. The token count on the diagram is illustrative.

Four ways agents fail

1 · Reward hacking
Asked to make the tests pass, it changes the tests. This happens in training (RLVR) and in real use. Defense: checks the agent can't modify. Software testing.
2 · Drift on long tasks
A model that handles 12-hour tasks half the time manages only about 1 hour at 80% success. Early mistakes build on each other. Defense: milestones and human review at checkpoints. Systems, project management.
3 · Prompt injection
Any text the agent reads can act as an instruction. Defense: the rule of two (next slide). Security.
4 · Cost and sprawl
62% of companies are trying agents, but only 23% have scaled them (McKinsey). Defense: measure results before scaling up. Software economics.
Bigger models won't fix these. They are engineering problems, and each one matches a course we already teach.
~1 min. Four clicks, one panel each. Panel 3 leads into the next slide.

Prompt injection: hidden instructions in ordinary content

1 · You ask
The assistant has three tools: it can read your mail, read your files and send mail. The risk comes from having all three at once.
2 · An email arrives
The email contains a hidden instruction. The model sees the email and your request as one block of text and can't reliably tell which part came from you.
3 · It follows the instruction
Real cases: Microsoft 365 Copilot (EchoLeak, 2025), Salesforce Agentforce (ForcedLeak, 2025), and the Nx npm attack (2025), where malware used developers' own AI coding tools to search for credentials.
Rule of two: an unsupervised agent should have at most two of these: private data, untrusted input, and a way to send data out.
This has reached peer review. In July 2025, 17 arXiv papers from 14 institutions were found with hidden prompts asking AI reviewers for positive reviews. ICLR 2026 treats this as collusion. Glossary 1: the model

Token A chunk of text (a word, part of a word, or punctuation) mapped to an integer. Models read and write tokens, not letters.
Parameters / weights The numbers learned in training. "175B" means 175 billion of them. Fixed once training ends.
Context window The maximum number of tokens the model can take in at once: prompt, files, history and its own output.
Pretraining Training on a huge text corpus to predict the next token. Produces knowledge and fluency, not an assistant.
Fine-tuning (SFT) Further training on curated examples, such as conversations, to change behavior. Changes the weights.
RLHF Reinforcement learning from human feedback: people rank answers, and the model is trained toward preferred ones.
RLVR Reinforcement learning with verifiable rewards: an automatic checker (tests, a math answer) supplies the reward.
Inference Running a trained model to produce output. What you pay for per token.
System prompt Hidden instructions the app places before the user's text in every conversation.
Prompt engineering Arranging the input so the desired continuation is also the most likely one.
Chain of thought / reasoning model Writing intermediate steps before the answer; reasoning models are trained to do so on their own.
Hallucination Fluent, confident output that is false. A side effect of training for plausibility.
Sycophancy Telling the user what they seem to want to hear; partly learned from human preference ratings.
Open weights The weight file is published and can be run locally. Not the same as open source: training data and code are usually not released.
Benchmark A fixed test set used to compare models. Vulnerable to contamination when test items leak into training data.

Glossary 2: the software around the model

Harness The program around the model that builds the prompt, runs tool calls, enforces permissions and manages context.
Tool / function calling The model writes a structured request for a named function; the harness decides whether to run it.
Agent A model and harness in a loop, with the model choosing each next action until the goal is met or a limit is hit.
Workflow A fixed sequence of model calls written in code. The developer, not the model, decides the steps.
Agentic workflow Loose marketing term covering both workflows and agents. Ask which one is meant.
RAG Retrieval-augmented generation: search documents at question time and paste the results into the prompt.
Embedding A vector representing a text's meaning; similar texts get nearby vectors. Used for retrieval.
MCP Model Context Protocol: an open standard for connecting harnesses (clients) to servers that offer tools and data.
Connector A product's name for an integration with an outside service, usually an MCP server.
Instruction file AGENTS.md, CLAUDE.md and similar: markdown loaded into every session to steer behavior.
Skill A folder with a SKILL.md and optional scripts. Only its description is loaded until the model chooses to read it.
Sub-agent A separate model instance with a fresh context window, started by another agent to handle a subtask.
Hook Code the harness runs before or after a tool call; can block it. A real guarantee, unlike instructions.
Prompt injection Instructions hidden in content the agent reads (a web page, an email, a file) that it then follows.
Reward hacking Satisfying the check instead of the goal, such as editing the tests so they pass.
